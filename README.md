# 微信「图片和视频」自动处理脚本 — 使用说明

## 一、这个脚本做什么

在微信「图片和视频」窗口中，自动逐张浏览图片/视频，并根据顶部工具栏的内容执行两种操作：

- **功能 A**：检测到「查看原视频」按钮 → 点击它 → 等待 2 秒
- **功能 B**：检测到「1:1」按钮 → 发送 `Ctrl+S` 打开保存窗 → 发送 `Alt+S` 确认保存 → 下一张

两个功能都可以用参数单独开启或跳过。随时按 **ESC** 停止。

---

## 二、示例截图

脚本只分析窗口**顶部 52 像素的标题栏/工具栏**，例如下面这张（原始截图裁剪后只保留标题栏）：

![标题栏示例](titlebar_example.png)

从左到右依次是：图钉、返回、前进、宫格、放大、缩小、**1:1**、文件夹、编辑、文字识别、截图、**下载保存**、更多、最小化、最大化、关闭。

脚本要识别的两个目标就在这一行里：
- **1:1 按钮**（B 功能的触发标志）——对应模板 `tpl_ratio.png`
- **查看原视频按钮**（A 功能的触发标志，视频文件才显示）——对应模板 `video.PNG`，位于工具栏右侧

## 三、准备工作

### 1. 依赖

只需三个库（不需要 OCR）：

```cmd
pip install pillow numpy opencv-python
```

### 2. 模板图片

脚本同目录下必须放置两张模板图（就是你自己截的图）：

| 文件 | 内容 | 用途 |
|---|---|---|
| `tpl_ratio.png` | 1:1 按钮截图 | B 功能触发条件 |
| `video.PNG` | 「查看原视频」按钮截图 | A 功能触发条件 |

示例（实际文件是你截取的原图）：

| 模板 | 尺寸 | 说明 |
|---|---|---|
| `tpl_ratio.png` | 约 39×30 | 建议只截图标本身，别带周围空白 |
| `video.PNG` | 约 69×20 | 只截「查看原视频(」固定文字部分，不要截后面的文件大小数字 |

> 提示：文件名的大小写要和脚本里的 `VIDEO_TPL` / `TRIGGER_TPL` 一致；如果改成英文名可避免某些环境下的中文路径问题（脚本已用 `imdecode` 规避，中文名也能用）。

## 四、运行

1. 打开微信的「图片和视频」窗口
2. 在命令行进入脚本目录并运行：

```cmd
cd /d Z:\docker-hermes\data\workspace\dsh
python media_ocr_bot.py
```

推荐用 `pythonw` 启动，避免命令行窗口抢焦点：

```cmd
pythonw media_ocr_bot.py
```

3. 启动后有 **5 秒准备时间**，提示：

```
已就绪：A=开 B=开。5 秒后开始，请把焦点切到窗口；随时按 ESC 停止。
```

在这 5 秒内把焦点切到微信窗口（可手工最大化，脚本不会改变窗口大小）。

4. 过程中随时按 **ESC** 停止。

## 五、运行逻辑

每一轮：

```
按右键（下一张）
   ↓
截取顶部 52px 横条
   ↓
A：匹配 video.PNG ──命中──> 点击「查看原视频」→ 等 2 秒
   │未命中
   ↓
B：匹配 tpl_ratio.png ──命中──> Ctrl+S → 等 0.8 秒 → Alt+S → 等 0.8 秒
   │未命中
   ↓
跳过，进入下一轮
```

- A 命中后本轮不再执行 B（互斥）
- 保存窗弹出期间脚本**不抢焦点**：下一轮按右键前会等待前台窗口回到主窗口（最多 10 秒），避免误操作保存窗

典型日志：

```
A 模板已加载: video.PNG (69x20)
B 模板已加载: tpl_ratio.png (39x30)
[1] A 匹配[NCC] conf=0.95 scale=0.80
[1] A 命中「查看原视频」@(2100,30) -> 点击后等待 2.0s。
[2] B 匹配[NCC] conf=0.94 scale=0.80
[2] B 命中触发模板 @(300,30) [NCC conf=0.94] -> Ctrl+S
    已保存（累计 B 1 张）。
[3] 无匹配 -> 跳过。
```

## 六、开关与可调参数

脚本顶部「可配置参数」区：

```python
ENABLE_A = True      # A：匹配 video.PNG「查看原视频」并点击
ENABLE_B = True      # B：匹配 tpl_ratio.png 后保存
```

| 需求 | 设置 |
|---|---|
| 只跑 A（点击原视频） | `ENABLE_A = True`, `ENABLE_B = False` |
| 只跑 B（自动保存） | `ENABLE_A = False`, `ENABLE_B = True` |
| 两个都跑（默认） | 都为 `True` |
| 只翻页不操作 | 都为 `False` |

其他常用参数：

| 参数 | 默认值 | 说明 |
|---|---|---|
| `WAIT_VIDEO` | 2.0 | 点击「查看原视频」后的等待秒数 |
| `CLICK_Y_OFFSET` | 8 | 点击点相对模板中心的下移量（点不准时微调） |
| `CONFIRM_KEY` | `"alt_s"` | 保存窗确认键，可改 `"enter"` |
| `POST_RIGHT_DELAY` | 0.2 | 按右键后等待界面刷新的秒数 |
| `AFTER_SAVE_DELAY` | 0.8 | Ctrl+S 后等保存窗出现的时间 |
| `AFTER_ENTER_DELAY` | 0.8 | Alt+S 后等保存窗关闭的时间 |
| `DEBUG_SAVE_IMAGE` | `False` | 设为 `True` 可在命中时保存 `debug_hit.png` 供排查 |

## 七、匹配算法说明

两个功能共用同一套匹配逻辑（`match_template`）：

1. **SIFT 优先**：尺度不变特征匹配，对窗口缩放、旋转、亮度变化不敏感
2. **NCC 兜底**：SIFT 失败时（小图标常提不出足够特征点），自动降级到多尺度归一化互相关匹配（缩放范围 0.4~1.4）

日志里的 `匹配[NCC]` / `匹配[SIFT]` 会告诉你本次用的哪条路径，`conf` 是置信度、`scale` 是相对模板的缩放比。

这个双保险设计使得窗口在 **1936 宽 ~ 2578 宽** 之间变化时都能正确识别（实测缩小到 1936 宽时，1:1 按钮 scale=0.80、conf=0.94，SIFT 失败后 NCC 成功命中）。

## 八、常见问题

**Q：启动后没反应 / 提示找不到窗口**
先打开标题为「图片和视频」的窗口。脚本按标题包含匹配，标题有后缀也能找到。

**Q：点击「查看原视频」点不准**
微调 `CLICK_Y_OFFSET`（当前 8）。排查时可临时把 `DEBUG_SAVE_IMAGE` 设为 `True`，生成的 `debug_hit.png` 是命中时的横条截图，可对照点击坐标。

**Q：Alt+S 不保存**
把 `CONFIRM_KEY` 改成 `"enter"`。不同保存对话框确认键不同。

**Q：匹配不上 / conf 很低**
- 确认模板图截取正确（只截图标/按钮本身，别带大面积空白）
- 确认窗口尺寸没有超出 0.4~1.4 倍的缩放范围
- 临时把 `DEBUG_SAVE_IMAGE` 设为 `True`，查看 `debug_hit.png` 中目标按钮的实际外观

**Q：保存窗弹出后被抢焦点**
脚本已处理：保存期间不调用 `activate`，下一轮按右键前等待前台窗口回到主窗口。如果仍有问题，不要在运行脚本时操作其他窗口。

**Q：中文文件名报错**
脚本用 `cv2.imdecode` + `np.fromfile` 读模板，中文路径可正常处理。如仍有问题，把模板改成英文文件名并同步修改 `VIDEO_TPL` / `TRIGGER_TPL`。
